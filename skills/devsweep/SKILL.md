# DevSweep: safe disk cleanup on macOS

DevSweep knows where developer tools keep regenerable data (Xcode DerivedData, Gradle and package-manager
caches, project build folders, Docker, leftover agent worktrees) and sorts every item into a safety tier.
Use its tools instead of deleting things with `rm`.

## Tools

| Tool | Effect | Cost |
|---|---|---|
| `disk_status` | Free space, a level (`ok`, `low`, `critical`) and, from the last scan, how much is safe to free | Instant, read-only |
| `plan_cleanup` | What a tier would remove, what each removal costs, and what stays protected and why | Read-only; scans (about a minute) if the cached scan is older than `max_age_minutes` (default 30) |
| `clean_safe` | Scans, then removes unprotected **Rebuilds** items only | Deletes files; `dry_run: true` only reports |

Tiers:

- **rebuilds**: regenerated by the next build or install (DerivedData, `~/.gradle/caches`, `node_modules`, `build/`).
  The only tier an agent can remove.
- **redownload**: no data loss, but needs the internet again (simulator runtimes, system images, NDKs). Plan only.
- **Has data** (simulators, emulators, archives with dSYMs): never offered to agents. The user reviews these in the app.

## Workflow

1. Call `disk_status`. Tell the user the free space and level. If `safe_to_free` is there, mention it.
2. Call `plan_cleanup` (tier `rebuilds`). Warn the user first that a scan can take about a minute.
   Summarize: total `would_free`, the largest few items with their `what_happens`, and anything notable under
   `protected` (for example an active project kept because it has uncommitted changes).
3. Ask the user before cleaning. A plan is not permission. Only skip asking if the user already told you to
   clean in this conversation.
4. Call `clean_safe`. Report `freed`, `free_before` → `free_after`, and any `skipped` items with their reason.
5. If the user still needs space, call `plan_cleanup` with tier `redownload` and show what it would free and
   what the user would have to download again. Agents cannot remove this tier: point the user to the DevSweep
   app or `devsweep clean --tier redownload`.

When disk space is the cause of a failure (ENOSPC during a build), do steps 1 to 4 and then retry the
original command once.

## Rules

- Never remove developer data yourself with `rm`, `xcrun simctl delete`, `docker system prune` or similar
  when DevSweep is available. DevSweep checks protections (running simulators, active projects, in-use
  versions, the user's "Always keep" list) that a raw command skips.
- Do not try to work around a protection. If something the user wants gone is protected, tell them the
  reason and let them decide in the app.
- If `clean_safe` returns an error saying agent cleaning is turned off, do not retry. Tell the user it is
  controlled by **Automation > Allow AI agents to clean** in DevSweep, or that they can clean from the app
  or menu bar themselves.
- Never touch the user's own large files (videos, installers, documents). DevSweep lists those only in its
  app, and agents should leave them to the user.

## Setup

If the tools are not available, DevSweep's MCP server is not configured. The user can add it with:

```bash
claude mcp add devsweep -- /Applications/DevSweep.app/Contents/Resources/devsweep mcp
```

Other agents (Cursor, Copilot, and so on) take the same command, `devsweep mcp`, as a stdio MCP server.
Without MCP, the CLI does the same thing: `devsweep status`, `devsweep clean --tier rebuilds --dry-run`,
then `devsweep clean --tier rebuilds --yes` after the user agrees.
